운영 업무와 Copilot

운영 팀은 사람, 프로세스, 시설, 기술을 조율해 조직이 멈추지 않고 돌아가게 합니다. 촉박한 일정과 복잡한 물류, 끊임없는 변화 속에서 빠르고 근거 있는 판단을 내려야 합니다. Microsoft 365 Copilot은 운영 담당자가 이미 매일 쓰는 도구에 AI 추론을 결합해, 반복 작업을 줄이고 위험 완화나 전략 기획, 부서 간 협업 같은 더 중요한 일에 집중하도록 돕습니다.

산업을 가리지 않고 운영 팀은 비슷한 압박을 마주합니다. 안전하고 효율적인 시설 유지, 여러 팀의 협업 조율, 돌발 상황 대응, 이해관계자 정렬입니다. Copilot은 다음을 도와 이 역량을 뒷받침합니다.

  • 기획과 실행 간소화. 구조화된 아이디어를 만들고 작업을 정리하며 복잡한 정보를 명확한 결과물로 바꿔 프로젝트 기획을 앞당깁니다.
  • 반복 작업 자동화. 상태 업데이트, 정형화된 질문, 검토 주기, 공급업체 연락 같은 반복 업무를 자동화하고 데이터를 취합하며, 일관된 답을 주는 노코드 에이전트를 만듭니다.
  • 복잡한 프로젝트 관리. 시설 확장처럼 여러 단계와 팀, 일정, 의존 관계가 얽힌 대형 과제에서 마일스톤을 시각화하고 위험을 살피며, 안내문 초안, 안전 문서 갱신, 요약 작성을 돕습니다.
  • 데이터 기반 판단. 문서, 이메일, 프로젝트 메모에서 정보를 빠르게 종합해 근거 있는 선택을 뒷받침합니다.
  • 커뮤니케이션과 이해관계자 정렬. 임원 브리핑, 현장 팀 안내, 공급업체 조율에 쓸 간결한 메시지와 발표 자료를 만듭니다.

실습 파일을 OneDrive에 올리기

이 모듈의 Copilot 프롬프트는 파일을 참조합니다. 먼저 실습에 필요한 파일을 모두 OneDrive에 올려 실습 내내 접근할 수 있게 합니다.

  1. 테넌트 제공자가 준비한 가상 머신에 로컬 Administrator 계정으로 로그인합니다. 암호는 Pa55w.rd입니다.
  2. Windows 작업 표시줄에서 Microsoft Edge를 선택합니다.
  3. 주소 표시줄에 https://www.office.com을 입력합니다.
  4. Welcome to Microsoft 365 화면에서 Sign in을 선택합니다.
  5. Sign-in 창에서 테넌트 제공자가 준 사용자 이름 userx@yourtenant.onmicrosoft.com을 입력하고 Next를 선택합니다.
  6. Enter password 화면에서 사용자 계정 암호를 입력하고 Sign in을 선택합니다.
  7. Stay signed in이 나오면 Don't show this again을 선택한 뒤 Yes를 선택합니다.
  8. Microsoft 365에서 Apps를 선택하고, 이어서 OneDrive를 선택합니다.
  9. OneDrive 왼쪽 위에서 +(add new) > File upload을 선택합니다.
  10. File Explorer에서 This PC > Local Disk (C:)로 이동해 ResourceFiles 폴더를 엽니다.
  11. 폴더 안 파일을 모두 선택하고 Open을 선택해 OneDrive로 올립니다.
  12. 업로드가 끝나면 화면 아래 가운데에 Uploaded 29 items to My files가 보입니다. Edge는 열어 둔 채 다음 단계로 넘어갑니다.
참고 · MRU 목록

Copilot에서 일부 파일이 제안 목록에 바로 뜨지 않을 수 있습니다. 어떤 Copilot 환경은 Most Recently Used(MRU, 최근 사용) 목록의 파일만 참조하고, 어떤 환경은 OneDrive를 직접 탐색합니다. 파일을 MRU 목록에 올리려면 해당 Microsoft 365 앱에서 그 파일을 한 번 열면 됩니다.

중요

Microsoft 365 Copilot은 OneDrive에 저장한 파일만 다룰 수 있습니다. PC에만 저장된 파일은 Copilot이 접근하려면 OneDrive로 옮겨야 합니다.

효과적인 프롬프트의 네 가지 요소

Copilot을 잘 쓰는 핵심은 프롬프트의 품질입니다. 좋은 프롬프트는 요청을 명확하고 실행 가능하게 만드는 다음 네 가지를 담습니다.

Goal (목표)

Copilot이 무엇을 하기를 원하는지 분명히 밝힙니다. 예: “최근 프로젝트 업데이트를 요약한 불릿 3~5개를 만들어 줘.”

Context (맥락)

왜 이 요청이 필요하고 누가·무엇이 관련되는지 배경을 줍니다. 예: “Client X의 ‘Phase 3+’ 캠페인 회의에 쓸 불릿이야.”

Sources (원본)

어디에서 정보를 찾을지 지정합니다. 예: “6월 이후의 이메일과 Teams 채팅에 집중해 줘.”

Expectations (기대)

톤, 스타일, 상세 수준을 정합니다. 예: “빨리 파악하게 쉬운 표현으로 설명해 줘.”

첫 프롬프트만 제공됩니다

각 연습의 첫 프롬프트는 이 네 요소를 담은 예시로 원문 그대로 제공됩니다. 나머지 프롬프트는 직접 작성하되, 이 예시를 본보기로 삼으면 됩니다. 원하는 결과가 나오지 않으면 프롬프트를 조금씩 바꿔 다시 시도합니다.

연습 1 · 운영 이니셔티브 간소화

원문Exercise 1: Streamline operational initiatives

운영 팀은 다양한 이니셔티브에서 효율을 끌어올리고 빠르게 적응하며 성과를 내야 합니다. Copilot은 지능형 자동화를 일상 워크플로에 녹여 이 요구에 대응하도록 돕습니다. Office 앱 전반에서 아이디어 도출, 분석, 실행을 하나로 묶어 더 민첩하고 협업적인 운영 기능을 만듭니다.

시나리오 · Adatum Corporation

50년 된 사옥의 보일러가 고장 났습니다. 운영 관리자인 여러분은 보일러를 수리할지 교체할지, 교체한다면 보일러에서 퍼니스(furnace) 방식으로 전환할지 판단해야 합니다. 하루 흐름 안에서 브레인스토밍 → 조사 → 임원 커뮤니케이션 → 의사결정과 공급업체 연락까지 Copilot으로 처리하는 것이 목표입니다.

하루 일과는 다음처럼 이어집니다.

  • 오전 · Whiteboard에서 발상과 정리. Copilot이 설치 프로젝트 아이디어를 스티커 메모로 만들고, 프로젝트 단계·위험 완화·가동 중단 최소화 같은 주제로 분류합니다.
  • 오전 중반 · Word에서 조사와 문서화. Copilot으로 보일러와 퍼니스를 비교하는 보고서를 만듭니다.
  • 이른 오후 · PowerPoint에서 설득. OneDrive에 저장한 비교 보고서를 임원 발표 자료로 바꾸고, 발표자 노트와 이미지, Q&A 슬라이드를 더합니다.
  • 늦은 오후 · Copilot Chat으로 의사결정과 연락. 지금까지 만든 결과물을 종합해 RFP 초안을 잡고 공급업체 연락과 리더십 결정을 준비합니다.

과제 1 · Copilot in Whiteboard로 프로젝트 아이디어 발상

원문Exercise 1, Task 1: Use Copilot in Whiteboard

이 과제는 AI가 돕는 스티커 메모 워크숍입니다. 여러 사람이 아이디어를 메모지에 적어 붙이고, 진행자가 이를 묶고 중복을 없애고 다듬는 브레인스토밍을 떠올리면 됩니다. 여기서는 Copilot이 참여자를 대신해 아이디어를 만들어 스티커 메모로 붙여 주고, 여러분은 진행자로서 메모를 편집하거나 지우고 최종적으로 분류를 맡깁니다.

  1. Edge에서 Microsoft 365 홈(https://www.microsoft365.com)에 로그인하고, 탐색 창에서 Apps 아이콘을 선택합니다. Apps 메뉴에서 All apps를 선택하고, 위쪽 앱 목록에서 All apps→를 선택합니다. All apps 창을 아래로 내려 Whiteboard를 선택합니다.
  2. Whiteboard for the web에서 새 Whiteboard 세션을 시작합니다.
  3. 세션의 Board name은 기본값이 Whiteboard X입니다. 이 필드를 선택해 이름을 Boiler installation project plan으로 바꿉니다.
  4. 아래 메뉴 막대 옆 Copilot 아이콘을 선택하고 Suggest를 선택합니다.
  5. Suggest content with Copilot 창에서 새 보일러 시스템 설치 단계를 제안하도록 요청합니다. 첫 프롬프트는 네 요소를 담은 예시로 아래를 그대로 입력합니다.
    프롬프트저는 Adatum Corporation의 운영 관리자입니다. 지은 지 50년 된 우리 건물은 보일러가 고장 나서 수리할지 교체할지 검토해야 합니다. 설치 작업을 시작하기 전에, 회사들이 새 보일러 시스템을 설치할 때 보통 거치는 단계를 브레인스토밍하고 정리하고 싶습니다. 전문 지식을 활용해서 보일러 설치 프로젝트를 성공적으로 마치기 위한 실행 가능한 단계를 빠짐없이 목록으로 제시해 줘.원문I'm the Operations Manager at Adatum Corporation. 팁

Copilot은 단순하고 단일 동작 프롬프트에서 잘 작동할 때가 많습니다. 먼저 응답을 받은 뒤 후속 요청으로 살을 붙여 나가면 됩니다.

  1. Copilot in Whiteboard는 기본적으로 아이디어를 여섯 개씩 만듭니다. 창에 뜬 여섯 개를 확인합니다. 만족스러우면 Insert (6)로 붙이거나, 더 깊이 파고들려면 Generate more를 선택해 여섯 개를 더 만듭니다. 버튼이 Insert (12)로 바뀌면 이를 선택해 12개를 붙입니다.
  2. Copilot이 노란 스티커 메모로 아이디어를 캔버스에 붙입니다. 실제 브레인스토밍처럼 특정 메모를 편집하거나 지우거나 잠글 수 있습니다. 메모를 더블클릭하면 위에 뜨는 메뉴 막대에서 Edit text(연필) 아이콘이나 다른 옵션을 쓸 수 있고, 끝의 줄임표 아이콘에서 삭제 등 추가 메뉴를 볼 수 있습니다.
  3. 제안한 아이디어가 위험 완화를 충분히 다루지 못한다고 느낍니다. 아래 Copilot 아이콘을 선택하고 Suggest를 선택합니다.
  4. Suggest content with Copilot 창에서 새 보일러를 건물 난방 시스템에 설치할 때의 위험을 완화하는 방법을 제안하도록 요청합니다.
  5. 위험 완화 아이디어 12개를 만들어 Whiteboard에 삽입합니다. 12개 메모 묶음은 테두리로 강조되며 이를 note grid라고 부릅니다. 다른 요소처럼 옮기거나 크기를 조절할 수 있습니다. 기존 메모 위에 겹치면 바깥 테두리를 잡아 옆으로 끕니다. 화면 밖으로 벗어나면 오른쪽 아래 Fit to Screen 아이콘을 눌러 전체를 맞춥니다.
  6. 이제 24개의 제안이 모였습니다. 원하는 메모를 골라 자유롭게 편집합니다.
  7. 편집을 마쳤으니 Copilot이 메모를 범주별로 정리하게 합니다. 범주 이름은 Copilot이 정하고 메모를 자동으로 나눕니다.
주의 · 화면 밖 메모

범주화를 고르면 Whiteboard는 현재 화면에 보이는 메모만 테두리 안에 넣습니다. 화면 밖 메모는 포함되지 않아 그대로 진행하면 분류에서 빠집니다.

  1. 모든 메모를 테두리 안에 넣으려면 두 가지 방법이 있습니다. 하나는 확대·이동으로 모든 메모를 화면에 보이게 하는 것이고, 다른 하나는 Ctrl+A로 캔버스의 모든 객체를 명시적으로 선택하는 것입니다. 이 과제에서는 Ctrl+A를 눌러 전부 선택합니다.
  2. Copilot이 화면 밖 메모까지 모두 선택했는지 확인합니다. 일부가 화면 밖이면 테두리 한쪽을 잡아 캔버스 안으로 끌어옵니다.
  3. 모든 메모가 보이는 상태에서 아래 Copilot 아이콘을 선택하고 Categorize를 선택합니다. Categorize selected notes 창에서 Categorize 버튼을 선택합니다.
  4. Copilot이 범주를 만들고 메모를 색깔별로 재배치합니다. 사각형이 작아 읽기 어려우면 Fit to Screen 아이콘을 여러 번 눌러 적당한 크기로 맞춥니다.
  5. 정리된 메모 아래 아이콘 트레이가 뜹니다. 범주가 마음에 들지 않으면 Regenerate 버튼을 선택합니다.
팁

Regenerate는 만족할 때까지 몇 번이든 누를 수 있습니다. 누를 때마다 범주 이름과 메모 배치가 바뀌고, 범주 수가 늘거나 줄기도 합니다.

  1. 여러 번 재생성하다 보면 어느 것이 좋았는지 헷갈립니다. 이전 분류로 되돌리는 기능은 아직 없지만 처음 상태로 돌아갈 수는 있습니다. Revert 버튼을 선택해 노란 메모 목록으로 되돌립니다.
  2. 다시 분류하려면 Copilot 아이콘 > Categorize를 선택하고, Categorize selected notes? 창에서 Categorize를 선택합니다.
  3. 이제 Regenerate 동작을 알았으니, 시간을 아끼려면 만족스러운 결과가 나올 때까지 한두 번만 누릅니다.
  4. 시스템 가동 중단 최소화에 대한 세부 단계가 빠졌음을 알아차립니다. 이미 정리했으므로 다시 편집 모드로 돌아가려면 Revert를 선택합니다.
  5. 편집 모드로 돌아온 뒤 필요 없는 메모를 선택하고, 아이콘 트레이에서 줄임표 아이콘 > Delete를 선택해 지웁니다.
  6. 앞서와 같은 방법으로, 새 보일러를 설치하는 동안 난방 가동 중단을 줄이는 방법을 제안하도록 Copilot에 요청합니다.
  7. 제안한 여섯 아이디어가 마음에 들면 캔버스에 삽입합니다. 기존 메모와 겹치면 옆으로 끌고, 화면 밖으로 벗어나면 Fit to Screen으로 맞춥니다.
  8. 이제 메모를 다시 분류하도록 Copilot에 요청합니다.
  9. 범주를 검토하고 만족스러울 때까지 재생성한 뒤 Keep it 버튼을 선택합니다.
  10. 브레인스토밍 세션 요약을 추가하고 싶습니다. Copilot 아이콘 > Summarize를 선택합니다. 요약이 나올 때도, 나오지 않을 때도 있으니 아래로 내려 확인하고 생성됐으면 Keep it을 선택합니다.
  11. 오른쪽 아래 Fit to Screen 아이콘을 눌러 모든 메모와 요약을 화면에 맞춥니다.

과제 2 · Copilot in Word로 운영 보고서 비교

원문Exercise 1, Task 2: Use Copilot in Word

보일러가 상당한 수리, 어쩌면 교체까지 필요하다는 사실을 알게 됐습니다. 이 기회에 더 효율적인 퍼니스 방식으로 바꾸는 편이 나을지 검토하려 합니다. 두 방식의 차이를 잘 모르니 공개 웹 데이터를 바탕으로 보고서를 만들어 경영진에 제출할 계획입니다. Copilot in Word로 보고서를 만들면서 두 가지 작동 방식을 함께 살펴봅니다.

Edit with Copilot의 두 가지 모드

Edit with Copilot이 켜져 있으면 Copilot이 문서 안 저자·편집자처럼 동작해 초안 작성이나 재작성, 요약을 문서에 직접 반영합니다(보통 확인을 거칩니다). 꺼져 있으면 Copilot Chat처럼 동작해 조사·요약·초안을 창에 보여 줄 뿐 문서를 자동으로 바꾸지 않습니다. 무엇을 넣을지는 여러분이 정합니다.

  1. Edge에서 Microsoft 365 홈으로 가서 탐색 창의 Apps를 선택하고 Word를 선택합니다.
  2. Word for the web에서 빈 문서를 만듭니다.
  3. Home 탭 리본에서 Copilot을 선택합니다. 프롬프트 필드의 더하기(+) 옆에 Edit with Copilot 아이콘이 있는지 확인합니다. 없으면 더하기를 선택하고 드롭다운에서 Edit with Copilot을 선택합니다.
  4. 프롬프트 필드에서, Adatum의 운영 관리자이며 현재 보일러 시스템을 퍼니스로 바꿀지 검토 중이라고 밝힌 뒤, 공개 정보를 바탕으로 대다수 상업용 건물이 쓰는 보일러 시스템을 설명하는 보고서를 만들어 달라고 요청합니다. 보고서에는 다음을 포함하게 합니다.
    • 각 시스템 개요(에너지 효율, 유지보수 요건, 개략적 비용 비교)
    • 기존 보일러에서 퍼니스로 전환할 때 고려사항
    • 1970년대에 지은 2층 상업용 건물에서 보일러를 퍼니스로 전환하는 평균 비용
    • 보일러에서 퍼니스로 바꾸면 현재 냉방 시스템에 영향을 주는지
    • 보일러와 퍼니스의 평균 결함률
  5. Copilot이 만든 보고서를 검토하며 각 항목의 상세 수준을 살핍니다.
  6. 이번에는 Edit in Copilot으로 문서를 다듬습니다. 프롬프트 필드에서 이 보고서를 임원(C-suite) 대상으로 더 알맞게 수정해 달라고 요청합니다.
  7. 결과를 검토합니다. Edit in Copilot이 켜져 있어 수정이 문서에 직접 적용되므로 복사·붙여넣기가 필요 없습니다.
  8. 이제 Edit in Copilot 아이콘을 선택해 끕니다. 아이콘이 프롬프트 필드에서 사라집니다.
  9. 프롬프트 필드에서 상업용 건물의 보일러와 퍼니스의 핵심 차이(효율, 유지보수, 수명, 일반적 용도 위주)를 요약해 달라고 요청합니다.
  10. 응답 차이를 확인합니다. 이제 Copilot은 채팅 모드로 동작해 문서를 자동으로 바꾸지 않고 창에 결과와 다음 제안을 보여 줍니다. Add to doc, Copy response 같은 아이콘도 제공합니다. 이 예에서는 줄임표(More actions) 아이콘을 선택하고 Export to Word를 선택합니다.
  11. 결과를 Word로 내보내면 새 탭에서 Word for the web이 열리고 내용이 들어옵니다. 다만 채팅 앞뒤의 불필요한 문구도 함께 들어오므로 저장 전에 지웁니다.
어느 방식을 쓸까

새 보고서를 만들 때는 상세한 정보가 필요하니 문서 생성 방식이 어울리고, 기존 문서에 넣을 조각을 만들 때는 짧게 요약된 채팅 방식이 어울립니다. 한쪽이 더 낫다기보다 보고 목적에 맞춰 고르면 됩니다.

과제 3 · Copilot in PowerPoint로 임원 발표 자료 만들기

원문Exercise 1, Task 3: Use Copilot in PowerPoint

앞 과제에서 만든 Heating System Comparison 보고서를 바탕으로, 경영진에게 두 난방 방식의 장단점을 이해시킬 발표 자료를 만듭니다. PowerPoint에는 빠른 슬라이드 생성용 표준 프롬프트와, 슬라이드·레이아웃·구조를 직접 편집하는 Edit with Copilot이 있습니다. 아이디어를 구상할 때는 채팅형을, 파일 안에서 직접 손볼 때는 Edit with Copilot을 씁니다.

  1. Edge에서 Microsoft 365 홈 > Apps > PowerPoint를 선택합니다.
  2. PowerPoint for the web에서 빈 프레젠테이션을 만듭니다.
  3. Home 탭 리본 끝의 Copilot을 선택합니다.
  4. Copilot 창에서 프롬프트 필드의 더하기(+) > Add work content를 선택하고, 앞 과제에서 OneDrive에 저장한 Heating System Comparison 보고서를 첨부합니다.
  5. 프롬프트 필드에 Edit with Copilot 아이콘이 있는지 확인합니다. 없으면 더하기 > Edit with Copilot을 선택합니다.
  6. 첨부한 파일을 바탕으로 임원 리더십용 발표 자료를 만들어 달라고 요청합니다.
  7. Copilot이 발표 관련 질문을 연달아 하면 원하는 답을 고르고 Confirm을 선택합니다. 슬라이드 템플릿 선택을 포함한 2차 질문이 나올 수도 있습니다. 템플릿을 고르지 않으면 흰 배경에 텍스트만 나옵니다. 판단을 맡기려면 Skip all을 선택합니다.
  8. Copilot이 이 정보로 슬라이드 목록을 만듭니다. 몇 분 걸릴 수 있습니다.
  9. 테스트에서 결과가 달랐습니다. 슬라이드가 자동으로 생성될 때도, 채팅 창에 개요와 여러 진행 옵션을 먼저 보여 줄 때도 있었습니다. 후자라면 개요대로 진행하라고 지시합니다. 어느 경우든 생성에 몇 분이 걸립니다.
  10. Copilot이 적용할 옵션을 제안하면 원하는 것을 받아들이고, 만족스러우면 슬라이드 생성을 진행하라고 지시합니다.
  11. Copilot이 슬라이드에 이미지를 넣을 수 있는지 봅니다. 이미지가 없는 슬라이드를 선택하고, 그 슬라이드 번호의 내용과 관련된 이미지를 만들어 슬라이드에 넣어 달라고 요청합니다.
  12. 1~2분 뒤 Copilot이 이미지를 만들어 슬라이드에 추가합니다.
  13. 난방 방식별 예상 수명 슬라이드가 없다는 점을 알아차립니다. 보일러와 퍼니스의 예상 수명을 조사해 새 슬라이드로 추가해 달라고 요청합니다. 제출 전에 슬라이드 목록에서 새 슬라이드가 들어갈 위치를 선택하면 빨간 선이 표시됩니다.
  14. 지정한 위치에 슬라이드가 추가됐는지 확인하고, 아니면 목록에서 끌어다 옮깁니다.
  15. 끝에 질의응답(Q&A) 슬라이드가 없습니다. 마지막 슬라이드 뒤에 Q&A 슬라이드를 추가해 달라고 요청합니다.
  16. 덱 끝에 슬라이드가 추가됐는지 확인하고, 아니면 끌어다 옮깁니다.
참고 · Copilot in PowerPoint의 한계

Copilot은 콘텐츠와 이미지, 디자인 제안을 창에서 만들지만 슬라이드 캔버스나 파일 구조에 직접 쓰지는 못합니다. 지금은 편집 엔진이 아니라 콘텐츠 생성 도우미로 동작합니다. Copilot이 제안하면 무엇을 적용할지는 여러분이 정합니다.

과제 4 · Microsoft 365 Copilot Chat으로 공급업체 연락 준비

원문Exercise 1, Task 4: Use Microsoft 365 Copilot Chat

지금까지의 작업을 실행 가능한 산출물로 모읍니다. 보일러 수리·교체·퍼니스 전환을 비교하는 의사결정 매트릭스, HVAC 공급업체에 보낼 RFP 초안, 경영진이 검토할 임원 요약입니다. Copilot Chat은 앞서 만든 자료에서 맥락을 끌어와 이를 구조화된 결과물로 종합합니다.

응답 모드 선택기

웹의 Copilot Chat에는 응답 깊이를 정하는 선택기가 있습니다. 기본값 Auto는 속도와 깊이의 균형을 맞춥니다. Work 모드에서는 선택기가 보이지 않고 Copilot이 깊이를 자동으로 관리합니다. Web 모드로 바꾸면 선택기가 나타나며, 한 번 켜지면 모드를 오가도 계속 보입니다. Excel의 선택기는 모델을 고르는 것이고 Chat의 선택기는 추론 깊이를 정하는 것으로 서로 다른 설정입니다.

  1. Edge에서 Microsoft 365 홈으로 갑니다. 이 과제는 OneDrive에 올린 내부 문서를 다루므로 Work를 선택합니다. Web은 공개 사이트를 검색하므로 여기에는 맞지 않습니다.
  2. 공급업체 선정 기준을 정리하는 것부터 시작합니다. 앞 과제에서 만든 Heating System Comparison 보고서를 이 프롬프트에 첨부합니다.
  3. 이 보고서에서 핵심 결정 요인을 요약해 달라고 요청합니다. 기준에는 비용, 에너지 효율, 가동 중단 영향, 장기 유지보수를 포함하게 합니다.
  4. 결정 기준을 검토하고 필요하면 다듬습니다. Copilot이 보여 주는 제안 프롬프트 중 기준을 개선할 만한 것을 제출합니다.
  5. 결정 기준이 마련됐으니, 보일러 수리·보일러 교체·퍼니스 전환 세 방안을 비교하는 의사결정 매트릭스를 만들어 달라고 요청합니다. 열에는 비용, 설치 시간, 에너지 효율, 예상 수명, 위험 수준을 넣고, 앞서 만든 결정 기준으로 채워 리더십의 관심사(비용·효율·가동 중단·유지보수)와 맞추게 합니다.
  6. 매트릭스의 정확성과 완전성을 검토합니다. 보증 조건과 규정 준수 요건 열을 추가해 달라고 요청합니다.
  7. 매트릭스를 더 실행 가능하게 만듭니다. 각 방안을 기준에 대해 평가·점수화하도록, 특히 위험 수준을 High/Medium/Low로 매기도록 요청합니다.
  8. 의사결정 매트릭스를 검토하고, 제안 프롬프트 중 개선에 도움이 될 것을 제출합니다.
  9. 매트릭스를 다듬었으면 이를 RFP와 임원 요약의 토대로 씁니다. 제목, 서론, 매트릭스 표, 그리고 공급업체 선정에 매트릭스를 어떻게 해석·활용하는지 설명하는 사용 안내 단락을 담아 다운로드 가능한 Word 보고서로 서식화해 달라고 요청합니다.
  10. Copilot이 다운로드 링크를 주면 의사결정 매트릭스 문서를 내려받습니다.
  11. 이제 RFP를 만듭니다. 방금 내려받은 매트릭스 문서를 프롬프트에 첨부하고, 결정 기준과 매트릭스를 활용해 HVAC 공급업체용 RFP 초안을 작성해 달라고 요청합니다. RFP에는 프로젝트 범위, 일정, 평가 기준을 포함하게 합니다.
  12. 제안 프롬프트 중 RFP 개선에 도움이 될 것을 제출합니다.
  13. RFP를 다운로드 가능한 Word 문서로 서식화해 달라고 요청하고, 링크가 나오면 내려받습니다.

    질문Packing 구역에서 나가는 임시 대피 경로는 뭐야?원문What's the temporary evacuation route from Packing?
    질문이번 주에 새 동에서 지게차를 사용할 수 있어?원문Are forklifts allowed in the new wing this week?
    질문SKU CHAI-12와 COFF-08은 언제 새 선반으로 옮겨져?원문When do SKU CHAI-12 and COFF-08 move to the new racks?
  3. 에이전트가 정책 파일을 인용하거나 요약하는 방식을 관찰하고, 답변의 완전성과 명확성을 평가합니다. 자기 서비스 정확도를 높이려면 갱신이 필요한 정책이 있는지 메모합니다.
  4. 이제 지식 문서에 없는 질문을 던집니다.
    질문파고 확장 프로젝트의 총비용은 얼마고, 어느 시공업체가 최저가로 입찰했어?원문What is the total cost of the Fargo expansion project, and which contractor submitted the lowest bid?

    기대 결과 · 지식 원본에는 재무·입찰·비용 내역이나 계약 조건이 없으므로, 에이전트는 정중히 거절하고 “contact the Project Controller” 같은 대체 안내를 해야 합니다. 두 번째 질문은 개요가 전기·HVAC·조명 같은 시스템을 일반적으로만 언급하고 구체적 기술 구매는 다루지 않으므로, 정보가 없다고 답해야 합니다.

  5. 범위 밖 질문에 적절한 대체 응답을 했는지 평가합니다.
  6. 이번에는 부분적으로만 다뤄지는 질문을 던집니다.

  7. 부분적으로만 다뤄진 질문에서 빠진 부분에 적절한 대체 응답을 했는지 평가합니다.

과제 4 · Copilot in OneNote로 안전 수칙 갱신

원문Exercise 2, Task 4: Use Copilot in OneNote

기존 안전 수칙 매뉴얼의 여러 부분이 확장으로 인해 뒤처졌음을 알게 됐습니다. 임시 공사 구역, 새 장비, 바뀐 동선, 갱신된 비상구가 새 위험과 절차를 만듭니다. Copilot in OneNote로 기존 절차를 검토하고, 영향받는 부분을 갱신하며, 운영 팀과 공유할 변경 요약을 만듭니다.

  1. Contoso Expansion Safety Procedures.onepkg 파일을 내려받아 OneDrive에 저장합니다.
  2. Edge에서 Microsoft 365 홈 > Apps > OneNote를 선택합니다.
  3. OneNote for the web의 All 탭에서 Contoso Expansion Safety Procedures 파일을 찾습니다. 안 보이면 검색 상자에 Contoso를 입력해 찾고 선택해 엽니다.
  4. 메뉴 막대에서 Copilot을 선택해 창을 엽니다. 공지가 뜨면 아래 Skip을 선택해 닫습니다.
  5. 이 안전 절차를 검토하고, 새 창고동 공사와 하역장 개선으로 영향받을 만한 부분을 짚어 달라고 요청합니다.
  6. 분석과 영향받는 부분을 검토합니다. 완화 권고 제안 프롬프트가 뜨면 제출하고, 없으면 그 요청을 직접 입력해 제출합니다.
  7. 응답과 제안 프롬프트를 검토하고 관심 있는 것을 제출합니다.
  8. 이제 안전 수칙을 갱신하게 합니다. 임시 공사 구역, 새 장비, 개정된 하역장 절차, 비상구 변경을 반영한 안전 수칙 초안을 작성해 달라고 요청합니다.
  9. 초안을 검토하고, 이를 제목과 아이콘이 있는 OneNote 페이지 형식으로 서식화해 달라고 요청합니다.
  10. 서식화가 끝나면 초안 끝의 Copy response 아이콘을 선택해 클립보드에 복사합니다.
  11. OneNote 노트북에서 +Add page를 선택하고 제목에 Expansion protocols를 입력합니다. 제목 아래 본문을 선택하고 Ctrl+V로 붙여넣습니다. 앞뒤의 불필요한 대화 텍스트는 지웁니다.
  12. 변경 사항을 공유하도록, 운영 직원과 나눌 안전 수칙 변경 요약을 간결하게 만들어 달라고 요청합니다.
  13. 요약을 검토하고 필요하면 수정을 요청합니다. 만족스러우면 Copy response 아이콘으로 복사합니다.
  14. 노트북에 페이지를 하나 더 추가하고 제목을 Summary of protocol changes로 정합니다. 복사한 내용을 붙여넣고 불필요한 텍스트를 지웁니다.
  15. 다음 과제에서 이 요약을 보내기 위해 PDF로 저장합니다. Summary 페이지가 열린 상태에서 File > Print으로 가서 Print 아이콘을 선택합니다. Printer 필드를 펼쳐 맨 위의 Save as PDF를 선택하고 Save를 눌러 OneDrive에 저장합니다.

과제 5 · Copilot in Outlook으로 안전 변경 이메일 보내기

원문Exercise 2, Task 5: Use Copilot in Outlook

갱신한 안전 절차 요약을 PDF로 저장했으니, 이제 파고 물류센터 운영 직원에게 배포합니다. 리더십은 다음 교대 전에 직원들이 새 위험과 제한 구역, 비상 변경을 이해하기를 바랍니다. Copilot in Outlook으로 명확한 안내 메일을 작성합니다.

  1. Edge에서 Microsoft 365 홈 > Apps > Outlook을 선택합니다.
  2. Outlook on the web에서 새 메일을 만들고, 앞 과제에서 OneDrive에 저장한 Summary PDF를 첨부합니다.
  3. 본문에서 첨부 파일 옆의 Open Copilot(연필) 아이콘을 선택합니다.
  4. Copilot 창의 프롬프트 필드에서, 파고 물류센터 운영 직원에게 보낼 메일을 만들어 달라고 요청합니다. 다음을 담게 합니다.
    • 첨부 PDF에 있는 안전 수칙 변경 요약
    • 보고서의 구체적 데이터 포인트(최소한 새 위험과 제한 구역)
    • 핵심 인사이트를 짚되 간결하고 실행 가능한 메시지
  5. 결과를 검토합니다. 비상 변경 정보를 포함해 달라고 요청합니다.
  6. 갱신된 메일을 검토합니다. Copilot이 새 버전(draft 2 of 2)을 만들었습니다. 뒤로 화살표로 draft 1로 갈 수 있지만, 최신 초안을 이어 쓰려면 앞으로 화살표로 draft 2로 돌아옵니다.
  7. 만족스러우면 Copilot 메뉴에서 Keep it을 선택해 원래 메일을 이 최종 초안으로 바꿉니다.
참고 · 초안 관리

요청마다 Copilot이 새 초안을 만듭니다. 이전 초안으로 이동해 유지하거나 그 초안을 수정하게 할 수 있습니다. 기본적으로는 마지막 초안을 보면서 다음 요청을 합니다.

  1. 초안이 실제 메일 본문에 들어갔는지 확인합니다. 삽입 뒤에도 Copilot으로 메일을 계속 수정할 수 있습니다. 문장·단락·전체를 바꾸려면 해당 부분을 먼저 드래그해 선택하고, 텍스트를 추가하려면 커서를 넣을 위치에 둡니다. 톤이 마음에 걸려 전체를 드래그하면 Open Copilot(연필) 아이콘이 나타납니다.
  2. Copilot 메뉴에서 Change Tone을 선택하고 톤 옵션을 고릅니다.
  3. 수정 결과를 검토합니다. 마음에 들지 않으면 다른 톤을 시도합니다.
  4. Copilot이 새 톤으로 두 번째 초안을 만듭니다. 만족스러우면 Replace를 선택해 현재 버전을 이 초안으로 바꿉니다.
  5. 비상 변경 단락을 더 늘릴지 판단하려고, 그 단락만 드래그해 선택하고 Open Copilot 아이콘을 선택합니다.
  6. Copilot 메뉴에서 Make it longer를 선택합니다. 늘린 버전을 읽어 본 뒤 원래가 낫다고 판단되면 Discard를 선택합니다.
  7. Copilot이 원래 비상 변경 단락이 그대로 있는 메일로 되돌립니다.
  8. 메일이 만족스러우면, 실습을 위해 본인 개인 메일 주소로 보냅니다. 메일을 받아 보고서를 열 수 있는지 확인합니다.
이 과제의 결과

파고 물류센터 확장 프로젝트로 시행되는 안전 수칙 변경을 운영 직원에게 알리는, 데이터 기반의 깔끔한 안내 메일을 받게 됩니다.
